# fastcast

Трансляция экрана ПК на другие устройства с минимальной задержкой. Первая цель — Google TV (4K), дальше 4K 120 fps. Клиенты только нативные, без браузера.

## Структура

```
apps/
  server/    Rust, пакет app, бинарь fastcast: захват экрана, кодирование и раздача по WebSocket
  client/    нативное приложение для Android TV / Google TV на Kotlin (MediaCodec → SurfaceView)
packages/
  media/     Rust: FLV-демуксер (с Enhanced FLV для HEVC), размер кадра из SPS, строки кодеков avc1.* и hvc1.*
```

Модули сервера устроены как в `price-percent-trading`: `src/<модуль>/{constants,services,types,test}`, на каждую сущность свой файл.

### Как идёт кадр

1. ТВ при подключении сообщает своё разрешение, частоту и кодеки, которые умеет декодировать. Сервер создаёт виртуальный монитор такого размера (драйвер Parsec VDD) и делает его единственным экраном, но только после того, как найден ffmpeg и проверен кодировщик (п. 3): пока они не готовы, мониторы ПК остаются включёнными. На время трансляции мониторы ПК выключаются, а весь рабочий стол с панелью задач и окнами переезжает на ТВ. Когда ТВ перестаёт смотреть, виртуальный монитор убирается, и мониторы включаются с прежними разрешением, частотой и расположением. Если сервер упал или его закрыли, драйвер сам убирает виртуальный монитор, и Windows возвращает прежнюю раскладку. Если драйвера нет или `VIRTUAL_DISPLAY=off`, захватывается монитор `CAPTURE_OUTPUT`, и мониторы не выключаются.
2. `ffmpeg` захватывает этот экран фильтром `ddagrab` (Desktop Duplication). Сам сервер переводит цвет в YUV по BT.709 в ограниченном диапазоне и помечает поток как BT.709. Встроенное преобразование NVENC считает по BT.601, из-за этого раньше искажались цвета.
3. Кодек выбирается по списку ТВ: HEVC, если ТВ его декодирует, иначе H.264. Режим `auto` пробует кодировщики по порядку: для HEVC NVENC → AMF → QSV, для H.264 NVENC → AMF → QSV → x264. Заданный `VIDEO_ENCODER` проверяется той же пробой и берётся для первого кодека из списка ТВ, который он умеет: `x264` кодирует только H.264, а если у `nvenc`, `amf` или `qsv` нет кодировщика HEVC, сервер переходит на H.264. Настройки задержки: `-tune ull`, без B-кадров, CBR.
4. Сервер читает FLV из stdout ffmpeg и рассылает кадры через `hub`: `broadcast` плюс кэш GOP от последнего ключевого кадра. Новый зритель сразу получает config и ключевой кадр, не дожидаясь следующего.
5. Захват стартует при подключении первого зрителя и останавливается через 5 с после ухода последнего. Вместе с ним убирается виртуальный монитор и включаются мониторы ПК. Если ТВ подключился с другим разрешением, экран и захват пересоздаются. Если ffmpeg не найден, ни один кодировщик не прошёл проверку или захват упал с ошибкой, виртуальный монитор убирается, мониторы ПК включаются, а сервер повторяет попытку через 5 с, пока ТВ смотрит. Другой запрос ТВ не ждёт этих 5 с. Если ffmpeg сам завершился без ошибки, он перезапускается через 1 с, а виртуальный монитор остаётся.
6. Клиент отдаёт кадры аппаратному MediaCodec, тот декодирует прямо в `SurfaceView`, в режиме низкой задержки. Рисуется только самый свежий кадр. Если клиент отстаёт, он пропускает кадры до следующего ключевого. Если связь пропала (например, ПК ушёл из сети), клиент сам переподключается. Первое сообщение сервера он ждёт до 15 с, а когда видео пошло, обрывом считается тишина дольше 5 с.

### Протокол (`ws://<host>:3278/ws`)

- Клиент подключается с параметрами `/ws?width=3840&height=2160&fps=60&codecs=hevc,avc`: размер и частота своего экрана и кодеки в порядке предпочтения. Без параметров сервер отдаёт H.264 с монитора `CAPTURE_OUTPUT`. Если зрителей несколько, действует запрос последнего подключившегося.
- Текстовое сообщение с конфигом:
  `{"type":"config","codec":"hvc1.1.6.L153.90","width":3840,"height":2160,"fps":60,"description":"<base64 hvcC или avcC>"}`.
  Приходит первым и повторяется перед первым ключевым кадром новой конфигурации кодировщика.
- Бинарный кадр: `[flags u8: бит 0 = ключевой][timestamp_ms u32 LE][access unit H.264 или HEVC, NAL-блоки с 4-байтной длиной]`.
- Клиент раз в 5 с присылает текстовое сообщение со статистикой в JSON, сервер пишет его в лог.
- Сервер пингует зрителя каждые 2 с. Зрителя, от которого 6 с ничего не пришло или который 5 с не принимает данные, сервер отключает.

### Автопоиск (UDP 3278)

Клиент раз в секунду рассылает `{"type":"discover","version":1}` на 255.255.255.255 и на broadcast-адрес каждой своей сети. Сервер отвечает ему напрямую: `{"type":"server","version":1,"name":"KOMPUTER","port":3278}`. Адрес сервера клиент берёт из отправителя ответа, вводить ничего не нужно.

## Сервер (Windows)

Нужны Rust и ffmpeg версии 6 или новее: `winget install Gyan.FFmpeg`. Сервер сам находит `ffmpeg.exe`: сначала рядом с `fastcast.exe`, затем в PATH, в том числе в сохранённом PATH пользователя и системы. Ищет он его заново при каждом запуске захвата. Поэтому ни консоль, открытую до установки ffmpeg, ни сам сервер перезапускать не нужно. При старте сервер пишет, какой ffmpeg нашёл, или предупреждает, что не нашёл. При каждом запуске захвата он пишет, какой ffmpeg взял.

Для отдельного экрана под ТВ один раз поставь драйвер Parsec Virtual Display Driver: https://github.com/nomi-san/parsec-vdd/releases. Права администратора серверу не нужны. Масштаб для 4K-экрана задаётся во время трансляции в «Параметры → Дисплей» (для ТВ удобно 200–300%). Windows настраивает его один раз и дальше запоминает.

```powershell
copy .env.example .env   # по желанию
cargo run
```

`cargo run` из корня репозитория собирает и запускает сервер. Профиль `dev` собирается с `opt-level = 3`, поэтому отладочная сборка не добавляет задержку.

Готовая сборка лежит в каждом релизе: `fastcast-server-windows-x64.zip` с `fastcast.exe` и `.env.example`. Среда выполнения Visual C++ вшита в `fastcast.exe`, поэтому для zip не нужны ни Rust, ни Visual C++ Redistributable, только ffmpeg.

Клиенты в той же сети находят сервер сами. При первом запуске Windows Firewall спросит разрешение: разреши доступ для частной сети, иначе ТВ не увидит ПК. Нужны TCP 3278 для видео (порт `WEB_PORT`) и UDP 3278 для автопоиска. Порт автопоиска не настраивается: ТВ ищет ПК только на UDP 3278.

Настройки в `.env`:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `WEB_HOST` / `WEB_PORT` | `0.0.0.0` / `3278` | адрес и порт сервера |
| `SERVER_NAME` | имя компьютера | имя сервера в списке на ТВ |
| `FFMPEG_PATH` | `ffmpeg` | путь к ffmpeg; заданный путь должен вести к существующему файлу, иначе захват не стартует, а ошибка называет этот путь; по умолчанию сервер ищет `ffmpeg.exe` сам, сначала рядом с `fastcast.exe`, затем в PATH |
| `VIDEO_ENCODER` | `auto` | `auto`, `nvenc`, `amf`, `qsv`, `x264`; заданный кодировщик проверяется пробой, `x264` кодирует только H.264 |
| `VIRTUAL_DISPLAY` | `on` | `on`: на время трансляции единственным экраном становится виртуальный монитор под разрешение ТВ; `off`: захват `CAPTURE_OUTPUT` без выключения мониторов |
| `CAPTURE_OUTPUT` | `0` | номер монитора, если виртуального нет |
| `CAPTURE_FPS` | `60` | частота кадров, если виртуального монитора нет; 120 включает 120 fps |
| `VIDEO_BITRATE_KBPS` | `40000` | битрейт; если картинка дёргается по Wi‑Fi, уменьши |
| `KEYFRAME_INTERVAL_SECONDS` | `2` | интервал ключевых кадров в секундах, от 1 до 10 |

Правила `.env`:

- Сервер читает `.env` из текущей папки или ближайшей родительской, затем `.env` рядом с `fastcast.exe`. Переменные, уже заданные в окружении, файл не перезаписывает. Если файла нет, это не ошибка.
- Значение с пробелами или обратным слэшем пиши в одинарных кавычках: `SERVER_NAME='Gaming PC'`, `FFMPEG_PATH='C:\Tools\ffmpeg\bin\ffmpeg.exe'`. Внутри одинарных кавычек ничего не экранируется, слэши не нужно удваивать. Без кавычек пробел обрывает значение, а `\` начинает экранирование, и строка не читается.
- Кодировка файла: UTF-8 (с BOM или без) или UTF-16 с BOM, например файл, созданный в PowerShell 5.1 через `>`. Другие кодировки (скажем, Windows-1251 с русскими буквами) сервер не читает.
- Файл, который нельзя прочитать или разобрать, останавливает сервер, а не игнорируется. Сообщение называет файл и строку: `fastcast stopped: C:\fastcast\.env line 3 cannot be parsed: "SERVER_NAME=Gaming PC" (write NAME=value, and put a value with spaces or backslashes in single quotes)`.

## Клиент (Google TV / Android TV)

Нужны JDK 17 и Android SDK: переменные `JAVA_HOME` и `ANDROID_HOME`.

```powershell
cd apps/client
.\gradlew.bat assembleRelease
```

Все сборки подписываются одним ключом: `%USERPROFILE%\.fastcast\fastcast-release.jks`, параметры в `keystore.properties` рядом с ним. Путь к `keystore.properties` можно задать переменной `FASTCAST_SIGNING`. Ключ хранится вне репозитория, держи его копию: без него обновить приложение на ТВ можно только через удаление.

Установка на телевизор, один раз:

1. На телевизоре открой Настройки → Система → Об устройстве и 7 раз нажми «Сборка ОС Android TV». Затем в «Для разработчиков» включи отладку по Wi‑Fi и подключи adb: `adb pair`, затем `adb connect`.
2. Выполни:
   ```powershell
   adb install app\build\outputs\apk\release\app-release.apk
   adb shell appops set dev.fastcast.client REQUEST_INSTALL_PACKAGES allow
   adb shell appops set dev.fastcast.client SYSTEM_ALERT_WINDOW allow
   ```
   На телевизорах TCL ещё разреши автозапуск, иначе после обновления приложение не откроется само:
   ```powershell
   adb shell appops set dev.fastcast.client AUTO_START allow
   adb shell appops set dev.fastcast.client ASSOC_START allow
   ```
3. Открой fastcast из лаунчера. Приложение покажет все ПК в сети, на которых запущен fastcast. Выбери нужный и нажми OK, само приложение никуда не подключается. ПК, к которому ты подключался в прошлый раз, помечен «Последний» и стоит в фокусе первым.

Управление с пульта:

- Список ПК: стрелки выбирают компьютер, OK подключает, «Назад» закрывает приложение. ПК, который молчит 5 секунд, пропадает из списка.
- Трансляция: OK или любая стрелка открывает меню «Продолжить / Статистика / Отключиться», без нажатий оно скрывается через 8 секунд. Info показывает статистику (fps, Мбит/с, разрешение, декодер). «Назад» закрывает меню, а без меню отключает трансляцию и возвращает к списку ПК.

Во время трансляции приложение переключает ТВ в режим с самой большой картинкой и частотой около 60 Гц (на 4K-панели это 3840x2160@60) и просит минимальную постобработку, то есть игровой режим: так ТВ не добавляет задержку и не меняет цвета. Серверу оно сообщает этот режим и аппаратные декодеры, которые его тянут, сначала HEVC, затем H.264. Если декодер HEVC падает два раза подряд и между сбоями не было нормального потока, до закрытия трансляции приложение просит у сервера только H.264. Паузы между переподключениями растут (1, 2, 5 секунд) и сбрасываются на 1 секунду, только когда поток отработал 5 секунд. После подключения приложение ждёт первое сообщение сервера до 15 секунд, потому что запуск захвата бывает долгим, а когда видео пошло, тишина дольше 5 секунд считается обрывом.

### Обновления

Дальше приложение обновляется само из GitHub Releases. Оно проверяет `releases/latest/download/fastcast-tv.json` каждый раз, когда открывается список ПК. Во время трансляции приложение обновления не проверяет. Неудачная проверка (нет сети, GitHub не ответил, манифест испорчен) не запоминается и повторяется при следующем открытии списка. Если вышла версия новее, приложение скачивает APK, сверяет размер и SHA-256, ставит его без диалога и запускается заново. Если установка не удалась или её отклонили, приложение запоминает эту версию, в том числе после перезапуска, и больше не скачивает и не предлагает её. Версия новее предлагается как обычно. Разрешения из шага 2 нужны, чтобы установка шла без подтверждения и приложение перезапускалось само.

## Релизы

Каждый пуш в `master` запускает `.github/workflows/release.yml`:

1. Клиент: тесты, lint и подписанная сборка, `versionCode` = 100 + номер запуска, `versionName` = `1.0.<versionCode>`.
2. Сервер на Windows: тесты и `cargo build --release`.
3. Релиз `v1.0.<versionCode>` с файлами `fastcast-tv.apk`, `fastcast-tv.json` (`versionCode`, `versionName`, `url`, `sha256`, `size`) и `fastcast-server-windows-x64.zip`.

Секреты репозитория: `ANDROID_KEYSTORE_BASE64` (ключ в base64) и `ANDROID_KEYSTORE_PASSWORD`.
