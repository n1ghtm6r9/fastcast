## Сейчас: окно сервера вместо `.env`

Цель: `fastcast.exe` открывает окно, и сервер в нём запускается сам. Все настройки меняются только в окне и хранятся в `%APPDATA%\fastcast\settings.json`. `.env`, `.env.example`, `dotenvy` и чтение настроек из переменных окружения уходят.

Решения:

- Окно на egui (eframe 0.37), отрисовка через OpenGL (glow): без браузера и WebView. Тесты окна на egui_kittest.
- Консоли нет (`windows_subsystem = "windows"`). Закрытие окна останавливает сервер и убирает виртуальный монитор.
- «Применить» сохраняет настройки и перезапускает сервер, если изменились его настройки; ТВ переподключается сам. Подробность журнала меняется без перезапуска.
- Журнал виден в окне (последние строки, местное время) и пишется в `%APPDATA%\fastcast\fastcast.log`, который перезаписывается при каждом запуске.
- Испорченный файл настроек не мешает запуску: берутся значения по умолчанию, а в журнал идёт предупреждение.
- Пустое имя сервера означает имя компьютера, пустой путь к ffmpeg — поиск ffmpeg самим сервером.

Шаги:

- [ ] 1. `SavedSettings`: что хранится и правится в окне. Значения по умолчанию, JSON через serde, числа в своих пределах, перевод в рабочие `Settings`.

- [ ] 3. Убрать env: `dotenvy`, `.env.example`, загрузчик `.env` с тестами, `settings_from`, `load_settings` и чтение переменных. Тестовые помощники захвата берут `SavedSettings`.
- [ ] 4. Журнал: кольцевой буфер строк, писатель для tracing, файл журнала, уровень меняется на лету.
- [ ] 5. Управление сервером из окна: `run_server(settings, stop, status)` вместо Ctrl+C. Управляющая задача умеет запустить, применить (перезапуск) и остановить. Статус: состояние, адрес, число ТВ, запрос ТВ, последний отчёт ТВ.

## Фаза 4: оптимизации

Подробности в `docs/superpowers/specs/2026-10-26-native-pipeline-design.md`, раздел Phases.

- [ ] NEON для GF(256) на ТВ, когда будет на чём проверить ARM.
- [ ] UDP segmentation offload.
- [ ] Срезы кадра (sub-frame slices).
- [ ] Управление перегрузкой по задержке: кодировщик меняет битрейт на лету.
- [ ] Оверлей с телеметрией задержки.
- [ ] AVC VUI bitstream restriction (без переупорядоченных кадров): декодеры Android сразу отдают каждый кадр.
- [ ] Очередь зрителя ограничивать по времени, а не по числу кадров: сейчас при плохом Wi‑Fi копится до ~4 с задержки.
